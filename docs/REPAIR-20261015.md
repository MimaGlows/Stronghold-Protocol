# 0.2.6 统一审计修复

本轮针对8个项目对话归并的199项要求核查，修复三个本机实例共享的执行与界面偏差。规则以用户后续确认的方案为准；3000、3001、3002使用同一代码构建，账号、好友、记录、回放及匹配限制继续各自保存。安装名称为“优化版卫戍”，3002保留游戏内实验标识。

## 战斗执行

- 自订规则执行版本为2；配置仍为v2、评分仍为v3。历史评分不重算。实际BOSS共享池使用每局数据视图，六人采用四人基准乘2，五人沿用原公式，再应用自订生命与额外回合强化各一次。
- 开局实际一人采用独立模拟基准及350层隐藏核心门槛；两至六人采用同盟基准。自订仍于第14回合主BOSS、可选第19回合最终BOSS结束；单人标准超过第8普通回合后沿用该末档。
- 普通额外回合的模板、抽取槽、敌人分配及倍率共用基准映射，多人使用第13回合，单人使用其最后普通回合。第15–18回合强化1.25／1.50／1.80／2.16；隐藏核心和第19回合使用对应有效模板及增援抽取。
- 游客权威生命最低0。BOSS合并时零生命游客贡献−10，非正队伍生命判负。债务余数跨生成动作轮转，最高生命并列者总量差不超过1；数量与赏金保留。
- 隐秘战争所有战前盟约信息入口显示锁，不从静态数据重建禁用信息；保留原版观战操作和战斗中必要详情。

## 协议、记录与兼容

- 真正补位时锁定本局隐私；关闭补位或成员退出不撤销。公开状态、结果、历史与回放支持旧匹配标记脱敏，原始账号归属只留服务端。
- 最近同游及其资料访问权限使用同一隐私标记判定，兼容顶层和结果内的`matchPrivacy`、`isMatchingMatch`、`matching`；先排除再取最近五局。离线历史工具同时清除有明确标记的旧社交缓存：仅在对局ID与完整账号归属一致时信任存档，缺失或错误归属不猜测，不移除好友关系。
- 接受匹配邀请后清理其他冲突邀请，不离开刚加入的目标队伍；失败保留来源。
- `room.custom`可选携带`difficulty`，与名称、配置按`revision`原子保存；旧请求不带难度时沿用当前值。房间状态的`scoreContexts`提供当前实际人数下四档预览上下文。
- 退出记录保存配置、原评分、开局人数、基准类型、规则执行版本与隐私。历史工具只从对局ID与完整账号身份一致的权威存档补齐；无法唯一恢复时显示信息缺失。
- `tools/repair-custom-records.mjs --root=实例目录 --report=报告文件`默认只读。维护停止后，附加`--apply --offline --backup=备份目录`执行原子修复。逐份读取，重复运行不会重写已修复记录；不在启动时扫描全库。
- 已有回放轨道保留，不用修复后的对局流程重新生成旧战斗。回放生成仍以已封存BattleSpec和原模拟签名为准。

## 界面与维护

- 匹配底部留白按区块实际高度更新；可以覆盖署名，操作按钮必须可完整滚出。设置难度为草稿，取消／Esc不写服务器。
- 匹配队伍存在时，顶栏不再形成独立层叠上下文，确保其中的设置弹窗始终高于固定底部匹配区块。匹配验收使用真实指针点击，并在桌面、手机横屏核验弹窗完成按钮的实际命中元素。
- 数据钩子在订阅后复查加载状态，避免缓存加载在渲染和被动订阅之间完成时，重连／暂停界面停在“正在载入模拟数据”。验收包含无后续通知的确定性竞态和六人联防连续重连。
- 全功能视觉验收覆盖首页安装、账号头像、调配持有自选、普通及自订房间、社交匹配、游戏阶段、统计及回放；遵守原有黑灰、薄荷绿、Bender与展示字体。
- 设置窗口使用可读字号和滚动内容；横屏登录避免上下同时裁切；技能详情正文最低12px并可滚动，保持战场几何和点击规则。
- 设置的可读字号随“小／中／大／特大”递增，保持棋盘几何不变；隐私开关有可访问名称，账号设置尚未加载时不可操作。窄屏调配工具栏分为两行，结算摘要及按钮不侵入玩家列表。
- 浏览器夹具使用独立伪账号目录；好友搜索、官方逐干员语音、服务器统计与退出回放失效断言按后续确认的现行规则验收，不恢复已被取代的旧行为。
- 新维护控制支持`drain`／`resume`，暂停新对局准入但不停止正在运行的对局。现有旧管理进程首次升级不具备该能力，采用全局空闲检查与原子`stopIdle`，发生竞争时恢复已停实例并等待，不中断对局。
