# 自订模拟 · 实验规则 v2

本功能仅用于 Stronghold-Protocol-Matchmaking 实验实例。独立、普通同盟与匹配保持原容量和内容。

## 房间与操作

大厅三个模拟方式并排；自订模拟创建五位密钥的自定房间，名称最多10个可见字符。
玩家自行选择空席，容量1/4/5/6，允许实际2、3人开局，观察者单列且不占席位。左上显示原版模拟难度图标及已选择的必选盟约；左下显示难度系数，右侧竖排列席。五位密钥沿用普通房间的逐字方框和复制操作。
房主修改设置会清除真人准备状态，正式开局锁定配置；容量不能低于真人与AI总数。缩容按原席位顺序将越界玩家移入空席，不踢人。玩家离开后可调小容量。自定房间不接收匹配补位。
已生效的历战合约在房间左侧显示矢量图标和名称；悬停或键盘聚焦可读详情，没有启用时不显示该区块。

设置分为基础与盟约、敌军、我方、经济与成长、回合与时间、**历战合约**。
必选盟约可不选，空选沿用常规抽取；最多3个，核心最多2个、附加最多1个。这样可以指定两个核心方向与一项辅助配合，同时保留随机禁用变化。界面禁用超额选择，服务端再次校验，不能用旧配置版本绕过；旧历史配置按当时数据保留。选择后保证可用而不自动激活，剩余候选不足时减少禁用数量。额外回合位于“基础与盟约”，悬赏狂欢位于“历战合约”。
敌生命50–300%、攻击/攻速40–400%、数量10–1000%；我方同范围，部署4–12，重新部署0–200%。
供给等级3保持原库存，12为四倍，商店格数不变；金币与盟约层数0.5–5倍，阶段时间60–200%。
金币只倍率新增收入，出售、退款、转移不放大，小数收益保留余数。

## 特殊规则

悬赏狂欢：R1开始，每回合从第一轮悬赏池的去重精英种类等概率抽取一种，每位玩家添加一只，再应用数量倍率。第二轮悬赏池的决策选择完成后，从该回合起改为第二轮池，并持续沿用；不固定切换回合、不复制BOSS。每只精英携带对应悬赏条目的原版逐只击倒赏金；同种存在多个条目时，以effectId稳定排序的首条作为对应奖励。
数量倍率只改变数量，不改变单只赏金。债务转移保留悬赏及其赏金，转入有效接收阵地；白鸟保留漏怪尚未领取的赏金，反复漏掉不发钱、之后击倒照常发钱。实际击倒者优先，其他死亡沿用原版阵地归属规则，淘汰账号不会吞掉赏金；同只敌人死亡仅结算一次，已击倒者不进入白鸟积存。新增赏金仍按金币收入倍率结算，并保留小数余数。
数量倍率应用一次；超过现有600个同时存活上限的敌人等待生成，未生成敌人仍参加超时漏怪结算。

额外回合保留R14领袖与原R15隐藏核心条件；未解锁核心时R15是普通强化战，继续到R19。
R15/16/17/18的敌生命、攻击、攻速、数量额外倍率为1.25/1.50/1.80/2.16，R19使用2.16。
R19从当前数据有效领袖模板均匀抽取；准备阶段不展示敌群与领袖身份。结算和回放保留实际结果。

背水一战与万无一失互斥，初始生命11/1。落网之鱼解除每轮10点漏怪扣血上限。
观光游客0生命在普通作战中仍存活。原版BOSS生命合并时每位零生命游客贡献−10，其他玩家贡献实际生命；合计≤0立即判负，BOSS战斗中全队生命归零也判负。个人显示0，隐藏核心沿用已有生命池，不重复扣除。
债务转移从淘汰后的下一回合起，持续重建淘汰席位的敌群及有效悬赏，覆盖普通、额外回合和BOSS增援，不复制BOSS本体。按该回合开战前个人生命选择接收者，平局按席位稳定分摊，BOSS使用合并前生命，不重复应用数量倍率。
隐秘战争隐藏选中策略，观看其他阵地沿用原版阶段权限。开场、准备和观察者准备信息隐藏启用/禁用盟约、特训敌人、敌群和BOSS预告，以锁图案说明效果。战斗中的实际敌人、详情和生命条保留；观察者可正常观看阵地，但盟约选择仍隐藏。
命运赌约：普通或BOSS回合成功结束，开战时存活的全员（含AI）各自达到原版完美作战条件，才给仍存活者各加1生命，包括零生命游客。协防补救漏怪不算完美，缺失、内部异常或合成结果不触发，淘汰者不复活，不限制于初始生命上限，同回合只发放一次。BOSS奖励在生命分配后、隐藏核心资格判断前应用。
野火不息恢复协防助战干员的初始生命、初始技力和可部署状态，击倒者复活；永久成长与装备保留。
重新部署0%在下一模拟帧恢复，不允许同帧反复部署。

白鸟河滩**不影响评分、不标星号**：漏怪不扣生命、不进入协防。R13/R18回灌；R14→15不另加清算。
回灌倍率=1+0.10×(当前回灌回合−首次漏怪回合)，作用于生命、攻击、攻速。
重复漏怪继续积存，保留首次回合及未领取的赏金；倍率由原始快照重算，不累计相乘，不重复领取同一敌人悬赏。
死亡来源的积存敌群移至存活阵地，未解决数量写入结算；领袖超时和直接扣生命能力仍生效。

五/六人采用[参考多人方案](https://github.com/YUYUYUYUYUYUYUTOUA/Stronghold-Protocol-Rhine/blob/codex/rhine-upstream-021/docs/MULTIPLAYER.md)的原版部分：核心BAN少1/2、最多两人协防、BOSS两两分组、九张悬赏，六人共享领袖池为同规则四人两倍，R10/12/14独立信标不占商店库存。
本实验不导入莱茵扩展干员与素材。
深入核对及许可依据见 [多人规则与授权对照](MULTIPLAYER-REFERENCE.md)。R14奖励信标依据发放标记即时转赠，即使留到后续回合才使用也即时；R10/R12奖励和普通商店信标仍在下个休整期送达，转赠保留精锐状态。
正式开局的实际人数决定基准，真人和AI均计入：1人使用原版独立模拟的敌人缩放、悬赏及BOSS基准，2–6人使用同盟基准；自订仍保留14/19回合。超出单人原表的普通回合沿用其最后一档，再叠加额外回合强化。中途减员不改变整局基准类型。

## 评分与提示

[ASSUMED] v3为配置相对压力估计，不是实测胜率。基准200/400/600/800。
评分=max(1,round(基准×敌军/我方×时间×合约))。
敌军=H^.65×A^.55×S^.55×N^.70；我方=H^.45×A^.85×S^.85×(部署/8)^.60×(供给/3)^.22×金币^.25×层数^.30。
时间=准备^(-.10)×作战^(-.25)×协防^(-.12)×((重新部署+.25)/1.25)^.18。
H超过2的评分折算=H×(1+.35×max(0,H−2))；A折算=A×(1+.25×clamp((A−2)/2,0,1))。
合约因子：额外回合1.35、悬赏狂欢1.20、落网之鱼1.15、有效债务1.15、野火.85、游客.20。
生命覆盖按基准策略平均生命/11或1的.35次方；游客不重复计生命和漏怪因子。
必选盟约折扣为核心.96/附加.985的原禁用概率次方；未改变可用性的选择不折扣。
白鸟河滩完全不进入公式，不间接关闭其他因子；其协防失效仅提示。
命运赌约因子为 `(L/(L+0.5×R))^0.35`：L是所选人数基准对应的策略平均初始生命（生命覆盖时为11或1），最低1；R为14或19。明确采用“半数回合全员完美”的估计。
v3追加“悬赏收益补偿”因子，避免只计算更多敌人的压力却漏算新增赏金：

```text
收益补偿 = (预计可用资金 / 基准可用资金)^(-0.25)
基准可用资金 = D + 0.75 × B
预计可用资金 = D + 0.75 × (B + C) × 数量倍率 × (1 + d)
```

D为对应单人/同盟数据的准备收入总和；B为各轮悬赏决策出现概率乘以候选击倒悬赏的平均数量、单只赏金和有效轮数；C为悬赏狂欢的逐回合精英赏金估计，最终回合赏金不计入能用于后续编队的资金；d在有效债务下取`0.15×(人数−1)/人数`，其他情况为0。
明确假设悬赏击倒率75%、债务转移平均淘汰压力15%，切池时点按数据表的第二类悬赏入口估计；实际随机决策和操作可使收入不同。没有上下文的数据预览采用D=130（额外回合每轮+12）、B=24、第一/第二轮单只赏金2.5/3的保守参考。
原有敌群与合约压力因子仍保留，奖励收益仅做经济补偿；敌群数量增大仍单调提高评分。白鸟无论实际回灌、赏金及其他词条组合如何，都完全不参与这项补偿或其他计分。
两倍显示高难，四倍要求开局确认；范围、互斥、非法盟约和占用席位是硬错误，敌群/库存/时限压力是风险提示。

## 服务端接口与兼容

`room.create.mode=custom`；`room.custom {config,name,revision}`；`room.seat {seat,revision}`。
房主权限、空席、容量、配置与操作版本均由服务端校验，旧四位加入兼容五位。
房间状态附加capacity/name/custom/revision/scoreContext/customEvaluation；每局使用独立GameData，配置版本2、评分版本3，读取v1配置时命运赌约缺省关闭。已有记录保留原分数与版本，不重算；v1战斗Golden沿用原夹具及旧计分基准。
BattleSpec.flags.custom携带实际战斗倍率；flags.customQueue启用保留超额敌人的生成队列。
自定战斗由服务端分片运行，避开旧客户端战斗报告的漏怪数量上限；普通模式保留原战斗执行方式。
统计并入原账户，标记自定，保存配置与评分版本，额外回合不新增奖励表外奖励。
历史列表、记录详情和结算统一显示“自定”，难度形如“终极模拟（4500）”，保存开局人数及single/multi基准类型，展示文本不改写原难度枚举。
自定等待房间提供好友列表、邀请、直接加入及观战。加入目标前确认切换，并携带预期来源房间/队伍及版本；目标容量、隐私和权限验证通过后原子转移，失败保留来源，进行中的对局禁止切换。成功后结束该账号冲突邀请，重复请求不重复转移。
自定战斗快照默认为5Hz，浏览器使用至少200毫秒插值缓冲；关键事件仍按原频率发送，准备状态及结算即时发送。普通模式的发送与插值保持原逻辑。

## 全模式100分钟与匹配隐私

全部模式正式启动起100分钟硬截止，包含确认/选择/准备/暂停/掉线；等待室和排队不计。
截止独立于阶段暂停，到期仅终止本局，返回房间；结果reason=duration_limit，未通关、保留已完成回合与奖励，无放弃处罚，重连可读取结束原因。
房间不常驻展示硬时限，只在配置可能超时时显示风险，实际到期仍弹窗。
纯匹配和实际接收队列补位的普通房间整局隐藏四位代码、不给近期同游记录；好友/链接邀请不触发。
服务端仍保留身份用于档案所有权与黑名单，公开房间/对局/历史/回放去掉代码；队伍与黑名单使用服务器临时不透明引用。
已知好友关系独立保留，匹配过程中好友列表不显示四位代码。

## 2026-10-15 游玩修复：回合、数值与观战

额外普通回合R15–18统一使用多人R13的模板和基础敌人倍率，单人使用其最后一个普通回合；仍按1.25/1.50/1.80/2.16强化生命、攻击、攻速和数量。R15若解锁原隐藏核心仍为核心战，R19随机领袖增援使用原主BOSS基准再强化；不再因超出原数值表回退到1倍。各倍率只应用一次，评分版本3与既有历史分数不变。

隐藏核心只能由主BOSS回合胜利解锁一次；R19胜利直接结算，失败直接判负。自订隐藏核心失败不得继续扩展回合。重复结算及过期阶段回调无效；原版普通模式保留主BOSS通关后隐藏核心挑战失败的原有结算规则。

自订和适用匹配规则的对局禁止开局重刷，服务端发起、投票和执行均拒绝；商店刷新保持有效。隐秘战争仅隐藏盟约及战前敌军情报，不增加观战限制。点击队友头像先展开“前往查看”，再操作切换；原有双击快捷保留。服务器和客户端战斗共用阶段权限，联防提供左右及全景，服务器明确发送成员和实际左右归属。

权威待扣生命变化按100毫秒采样并使用现有100毫秒公共状态节流，合并等待上限200毫秒；客户端战斗计数变化可提前发送进度，平稳期间保留原周期。状态未变化不重复广播，不提高战斗快照频率。待扣值不提前扣正式生命，按权威规则处理10点上限、落网之鱼、白鸟免扣和生命下限，结算时清除。


当前基准映射、共享BOSS池、游客生命、债务平摊、隐秘遮罩和记录兼容见[统一审计修复](REPAIR-20261015.md)。配置v2和评分v3保持不变，自订规则执行版本为2。
