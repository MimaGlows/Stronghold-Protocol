# 2026-10-11 Windows 定制修复

本次保留 v0.2.3 游戏规则、伪账号、统计、头像和设置同步、官方调配语音、最近 30 条记录的回放资格以及两行署名。开发依赖只在隔离源码中。

## 回放

客户端通过原有已鉴权的 `/api/replays/:id`、匿名分享和好友历史接口取得 `tracks=1` 索引，随后以 `field`、`chunk` 取片段。片段最多 10 秒游戏时间、8 MiB 解码 JSON。LRU 缓存按解码 JSON 字节计最多 32 MiB；这不是浏览器进程总内存上限。索引、模型、纹理及浏览器对象需要额外内存。

私有 `.tracks` 目录是可重建的派生缓存。原 `.json.gz` 存档不改写。分块包含完整首帧、此前生成单位及形态信息；HUD 使用低频进度轨道。跳转和关闭中止过时请求。休整场景初始化同时提交单位及静态快照；更换渲染视图时重建场景。图形上下文丢失后切换 DOM 简化视图。

完整轨道依据存档、编码、场地及帧结构判断播放兼容性，界面构建版本不同不再判定过期。待生成轨道另核对模拟代码及实际共享依赖的签名；输入包含自己的数据快照。保留已知同引擎 v0.2.3 旧指纹的生成兼容。每次启动与归档扫描产生 `logs/replays/compatibility-report.gz`；升级前可运行只读工具：

```powershell
.runtime\node.exe tools\check-replay-compatibility.mjs --dir logs/replays --out replay-compatibility.json
```

真正超过账号最近 30 条资格时，沿用既有清理规则。格式不兼容保留原始轨道；此前已删除的轨道不能恢复。保留历史结算与原失效原因。

## 邀请、切场、继续对局

好友快照必须包含有效数组；不完整快照不能清空已有列表，旧账号响应无效。署名由 Preact 专用组件拥有，不再从外部脚本插入组件管理的节点。仅首页及模拟选择页显示。

切场确认沿用递增请求序号。新收到的队友休整场地不能被 own-prep 初始化分支标记为过时；确认后统一切换观看状态。视图重建不复用旧场景的初始化标记。

删除官方外观的恢复按钮及弹窗。自制“继续当前对局”仅检查当前代号及四位编号在服务器仍存续的实际活动对局，通过已有登录、重连及接管审批继续。服务器重启、主动退出或结算后不可继续，不使用官方恢复协议。

邀请通知默认开启，保留显式关闭设置。真正点击时请求浏览器授权；自动进入页面不会偷偷模拟点击。授权失败、拒绝或不安全上下文继续使用游戏内邀请；网页关闭后不接收 Web Push。系统是否显示通知还受浏览器及 OS 设置影响。

## 通讯

Z＋点击策略、公共或个人机变、悬赏、补给、商店候选及奖励，只发送意向。服务器从当前候选生成名称，验证阶段、轮次、已领取状态及个人 choiceId，不执行选择或购买。策略草稿位于第 0 回合，通讯协议覆盖这一边界。

战斗干员标点绑定 battleId、所属玩家和 uid，服务端核对部署及观察权限；客户端按当前存活单位定位，单位消失则不画标记。自身、队友及合并战场均使用同一归属逻辑。标点维持 125ms / 10 秒 40 次；无线电独立 1 秒 / 10 秒 5 次。新增消息写入通讯回放轨道。
